# Stage 4 — Docker 3-Tier

## Local Compose (Mac)
1. Stop existing Gunicorn with Ctrl+C. Stop but do not delete legacy DB: `docker stop memo-dev-db`. Never run both DB containers on the same volume simultaneously.
2. Keep existing `.env`; edit PUBLIC_ORIGIN=http://localhost (no :5000), COOKIE_SECURE=false, add DB_ROOT_PASSWORD (random string). Keep DB_PASSWORD and JWT/CSRF keys unchanged. Existing DB volume retains its original accounts/root password; new root env does not reset it. For fresh DB use a different DB_VOLUME_NAME and matching credentials.
3. `docker volume create memo-dev-data` (idempotent; use chosen name if different).
4. `docker compose up -d --build`; `docker compose ps`; `docker compose logs --tail=50 was db web` (redact sensitive output). Visit http://localhost. `curl -i http://localhost/health`.
5. `bash scripts/check-network.sh`. This uses a temporary Python probe sharing the Web network namespace, with positive control and DB direct IP test, without joining backend network. Check no ports published for WAS/DB. From another machine test `nc -vz -w 3 SERVER_IP 3306` and 5000; compare HTTP 80 success. If using macOS nc use `-G 3` instead. Local Docker Desktop VM isolation differs from Linux host.
6. Write a unique memo, `docker compose up -d --force-recreate was`, verify memo; `docker compose up -d --force-recreate db`, wait for healthy, verify memo again. Never delete volume. `docker compose down` preserves external volume.

## Ubuntu Swarm
- `uname -m` on server; x86_64=linux/amd64, aarch64=linux/arm64. On Mac: `docker login -u YOUR_DOCKERHUB_ID`; `docker buildx build --platform linux/amd64,linux/arm64 -t YOUR_DOCKERHUB_ID/cloud-security-memo:stage4 --push .` (choose single target for speed if desired). Registry username is not necessarily GitHub ID.
- Copy stack.yml, nginx/nginx.conf, scripts/init.sh to server, e.g. scp. Install Docker on Ubuntu if needed. `docker swarm init` only if not already active. `docker node ls`; select one DB node, `bash scripts/init.sh NODE_NAME`. Script keeps existing secrets; only label one node. Test password prompt: enter evaluation password. Existing production DB volumes must already match secrets; this script does not rotate passwords.
- `export WAS_IMAGE=YOUR_DOCKERHUB_ID/cloud-security-memo:stage4`; `export PUBLIC_ORIGIN=http://SERVER_PUBLIC_IP`; `export COOKIE_SECURE=false`; `docker stack deploy --with-registry-auth -c stack.yml memo`. For private images log in on manager first. Stack does not auto-read .env and has no build/depends_on. `docker stack services memo`; `docker service ps memo_was`; `docker service logs --tail 50 memo_was`; `curl -i http://localhost/health`.
- Security group: TCP 80 public for evaluation; SSH 22 restricted to administrator or deployment runner; never expose 3306 or 5000. Multi-node Swarm internal ports 2377 TCP, 7946 TCP/UDP, 4789 UDP only between trusted nodes as needed; not public. HTTPS requires actual TLS termination and exact HTTPS PUBLIC_ORIGIN plus COOKIE_SECURE=true; this patch implements HTTP only.
- DB uses node-local volume memo-prod-data and placement label. No cross-node replication or VM/DB HA. Only WAS replicas are updated; start-first does not guarantee zero errors. Test during deployment separately. Runtime DB user has schema-level privileges for initialization, not root; stronger DDL/DML separation is future work.
- For Swarm DB access test, run on node hosting each task: use `docker ps --filter label=com.docker.swarm.service.name=memo_web` (or memo_was/memo_db). Inspect actual network membership and published service ports with `docker service inspect`. For direct TCP tests use temporary Python probe sharing web task network namespace (same method as local script; use registry image instead). Get DB IP from WAS via socket.gethostbyname('db'); test web -> was positive and web -> DB negative; external host test 3306/5000. No Docker admin isolation claimed.
